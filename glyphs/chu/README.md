# `glyphs/chu/` —— 楚文字层

战国**楚系简帛**文字的字形：汉典「书法」「楚系簡帛」栏目里的实例，
依汉典《服务条款》第四条以 **CC0 1.0** 释出。

规模：**11,039** 个字形，覆盖 **4,171** 个现代字，按 **26** 个出土文献分桶
（上博藏戰國楚竹書分（一）（二）两册，故文献桶比文献种数多一个）。

这一层与金文/隶书层同源（都是汉典「书法」实例），但**分桶维度不同**，
所以看这一层的方式也不同。

## 文件

| 文件 | 内容 |
|------|------|
| `<条目号>.svg` | 字形，文件名 = 本仓库条目号（≥4 位十进制，如 `0001.svg`） |
| `index.csv` | 本地字形索引：一行一个字形（条目号 → 文件 → 现代字 → 出土文献 → 位置 → sha256） |
| `books.csv` | **文献代号对照表**：题记里的出土文献代码 → 全称、归属、收录与否 |
| `books_xxt.csv` | **小學堂出處表对照**：小學堂「楚系簡帛」库的出處簡號 → 全称 → 對應漢典代號（兩庫代號**不是同一套**，不能直接换名） |
| `staged.csv` | **未发布登记表**：不进本层的字形逐条登记（现代字、题记、上游 URL、sha256、底本页.行、未收录原因） |

## 键：条目号

这一层用**本仓库条目号**做键，不用现代字码位——因为楚文字**一字多形**：
同一个现代字在不同出土文献各有各的写法（如「人」在郭店、包山、上博、新蔡各有写法），
按现代字命名会撞车。

条目号的规则是仓库通用规则：**按「现代字码位 → 汉典字形编号」排序后重排 1..N**，
所以它是**整层内容的函数**——层里增删字形会整体重排。
**下游要按 `index.csv` 解析，不要硬编 `NNNN.svg` 文件名。**

## 一字多形：按出土文献分桶，不按时代

战国楚简的题记里**一个时代词都没有**（传世楚简都是战国中晚期的，汉典也没标时代），
所以这一层**不能按时代分桶**——按时代分桶会退化成「每字只收一个」。

分桶维度是**出土文献**：题记开头的文献代码（「郭」「包」「上」「新甲」「望」「信」
→「天卜」「九」「帛甲」……）。每个出土文献最多取 1 个实例（`--max-per-book 1`），
每字最多 5 条（`--per-char 5`）。这样得到的是**楚文字内部的写法演变链**。

题记的切法（`src/fetch_zdic_glyphs.py` 的 `parse_caption_chu`）：

| 题记原文 | 文献代码 | 篇名 | 位置编号 | 含义 |
|----------|----------|------|----------|------|
| `剌郭.性.30` | 郭 | 性 | 30 | 郭店楚簡《性自命出》第 30 字 |
| `包2.241` | 包 | — | 2.241 | 包山楚簡第 2 簡第 241 字 |
| `上(2).容.28` | 上 | 容 | 28 | 上博藏戰國楚竹書第二冊《容》篇第 28 字 |
| `新甲3.318` | 新甲 | — | 3.318 | 新蔡葛陵楚簡甲組第 3 簡第 318 字 |
| `帛甲5.19` | 帛甲 | — | 5.19 | 長沙楚帛書甲篇第 5 行第 19 字 |
| `𡩟天卜` | 天卜 | — | — | 天星觀卜筮祭禱簡 |

`index.csv` 里 `source_book` 记的是**文献全称**（由 `books.csv` 把代码换掉），
`book_part` 记篇名，`source_number` 记位置编号，`variant` 记**题记原文**。

## 一个字形可以挂多个现代字：正字与異體字并存

层里的键是 **(现代字码位, 字形键)**。同一个字形可能被记成好几条，
因为**同一笔字形有多种释读**：正字（楷書写法）与異體字（同一个字的另一种写法）
是两个不同的 Unicode 码位。

汉典侧的现状：**11,039 条记录只有 5,304 个唯一字形键**——3,074 个字形挂了多个现代字
（最多的一个 `52_EDCA` 挂了 11 个，如「㑴」与「侵」同形）。

小学堂批次给的是**楷書正字**（1,829 个），汉典记的是**異體字读法**（4,171 个），
两边**不重合**：交集 1,827，只有小学堂有的 2 个（蛙、陼）都是基本区规范字。
所以合并后层里「正字 + 異體字」并存是**正常语义，不是重复**——
正字身份本身是汉典层缺的那一条，这正是「小学堂补缺口」的意思。

> **临时身份条目**：小学堂有些字頭只给**字体排版槽位码位**（私用區），
> 不是 Unicode 汉字码位。这类条目 `modern_char` 与 `unicode` **都留空**，
> 身份线索记在 `identity_confidence`（`pua-slot`）与 `modern_char_slot`
> （`<字体号>_<码位>`）——**不拿私用區码位冒充汉字码位**
> （与甲骨层 glyph_id 380/916 同口径）。合并器对这类条目用
> `slot:<字体号>_<码位>` 作去重与排序键，**该键不进 `index.csv` 的 `unicode` 列**。

## 这一层只收楚系材料：别的字形不删，只是不发布

漢典的「楚系簡帛」栏目是**按栏目**归的，不是按书体归的——同一个栏目里同时有：

| 材料 | 题记代号 | 归属 |
|------|----------|------|
| 楚系简牍与帛书 | 郭、包、包牘、包簽、上、新甲、新乙、新零、曾、望、信、九、天卜、仰、牌、帛甲、帛乙、帛丙、簽 | **本层收录** |
| 秦系简帛 | 「秦」（《睡虎地秦簡文字編》《秦簡牘文字編》《秦簡墨書集成字形表》等底本） | 另立秦文字层 |
| 傳抄古文 | 「磚」（徐在國《傳抄古文字編》系統） | 另立傳抄古文层 |
| 全称后来补上的楚系代号 | 「天策」「香中大」「常」「雨」「范」「馬」 | **本层收录**，全称见下节 |

筛选由 `books.csv` 的 `include` 列决定，**表里没有登记的代号一律不收并单独报出来**——
新代号出现时不会被悄悄放进来（判断「这是什么材料」不能靠默认值）。

**被筛掉的字形不删除**：它们连同登记表（现代字、题记、上游 URL、上游原件 sha256、
摹本底本与页.行、未收录原因）写到 `--staged-out` 指定的目录，
并把登记表同步一份到 `glyphs/chu/staged.csv`（随层一起发布，便于将来另立层时直接取用；
字形本体留在本地暂存目录，不随层发布）。

### 六个代号的归属与全称：跨栏实测 + 小學堂出處表

「天策」「香中大」「常」「雨」「范」「馬」这六个代号，早期查不到具体指哪部出土文献。
现在两个问题都有答案了，但**两问的证据来自不同来源，分开记**：

1. **归属要证实，不靠猜。** 用 `src/probe_zdic_book_tabs.py` 做跨栏实测——同一个文献代号
   如果在汉典别的书体栏（秦系簡牘 / 傳抄古文 / 隸書 / 篆書 / 金文 / 甲骨文）里也出现，
   它的家就在那儿；**只出现在「楚系簡帛」栏**才是楚系材料。实测结论：这六个代号只出现在
   楚系簡帛栏（「秦」「磚」则分别在秦系簡牘栏与傳抄古文體系里）。
2. **全称从小學堂出處表来。** 2026-10-31 取回小學堂「楚系簡帛」库的出處表
   （<https://xiaoxue.iis.sinica.edu.tw/chuwenzi/Reference/Reference>），六个代號在全称列里逐一對上了：

   | 代號 | 全稱 | 摹本出處 | 本层条数 |
   |------|------|----------|----------|
   | 天策 | 江陵天星觀1號墓遣策簡 | 《楚系簡帛文字編》湖北教育出版社1995年7月版 | 321 |
   | 香中大 | 香港中文大學文物館藏簡牘（甲、戰國楚簡） | 《香港中文大學文物館藏簡牘》中文大學文物館出版社2001年版 | 53 |
   | 常 | 常德市德山夕陽坡1、2號墓竹簡 | 《楚史與楚文化研究》求索增刊1987年版 | 35 |
   | 雨 | 江陵雨臺山21號墓竹律管墨書文字 | 《湖北出土商周文字輯證》武漢大學出版社1992年版 | 38 |
   | 范 | 江陵范家坡27號墓竹簡 | 《楚系簡帛文字編》湖北教育出版社1995年7月版 | 14 |
   | 馬 | 江陵馬山1號墓竹簡 | 《江陵馬山一號楚墓》文物出版社1985年2月版 | 4 |

   **「常」有一处必须讲清楚**：出處表只列「常2」= 2 號墓，而漢典層的「常」桶
   **同時含 1 號墓與 2 號墓**（實測：編號首段 1 有 26 條、2 有 9 條，題記作「常1」「常2.1」）。
   全稱寫成「1、2號墓」是**兜底聚合**，其中 1 號墓那半是按「常N → 夕陽坡N號墓」的編號規律
   **推定**的——`books_xxt.csv` 里那行帶〔待考〕標記，**不得當成已核實**。
3. **兩庫的簡號不是同一套，不能互相換名。** 漢典 chuwenzi 欄的「磚」是傳抄古文字編的宋古文磚，
   小學堂楚系庫的「磚370」是江陵磚瓦廠370號墓竹簡——**是兩件材料**；漢典的「秦」是睡虎地秦簡，
   小學堂的「秦1/13/99」是江陵秦家嘴1/13/99號墓竹簡。對照見 `books_xxt.csv`，
   `zdic_code` 留空即表示**漢典那一欄沒有對應**，收不收由本層自己的 `books.csv` 決定。
4. **出处照样可追。** 每条都记着摹本底本《楚系簡帛文字編》（增訂本）的**页.行**
   （`source_base_pages`），读者据此可回原书查到字形在哪个文本。

**重导的差异范围**：据此改 `books.csv` 的 `corpus_full` 再跑一遍合并与入库，结果是
**只有 `source_book` 变了（465 条）**——字形 SVG **零变更**、条目号不变、文献分桶仍是 **26** 个。

### `books.csv` 的列

| 列 | 含义 |
|----|------|
| `code` | 题记里的文献代码（原文，如「郭」「包」「上(1)」） |
| `corpus_full` | 文献全称；**查不到就留空**（留个代码比编一个书名好） |
| `script_belong` | 归属：`chu` / `qin` / `chuanchao` |
| `include` | `yes` = 收录进本层；否则不收 |
| `reason` | 收录/不收录的理由（进未发布登记表） |
| `evidence` | 考证依据（书名、凡例条文、网址） |

`books.csv` 现在**兼管两库的代码**：漢典 chuwenzi 欄的代码（「磚」「秦」→ `include=no`），
以及小學堂楚系庫的出處簡號（「磚370」「秦1/13/99」「帛殘」→ `include=yes`）。
两套代码**不是同一套**，不能互相换名——所以小學堂那一侧另有一张 `books_xxt.csv` 做对照。

`books.csv` 里每个代号的依据都指向可查的来源，例如：

- 「天卜」——简帛網〈天星觀「卜筮祭禱」簡釋文輯校〉明言《楚系簡帛文字編》中全部「天卜」類條文
- 「上」——《楚系簡帛文字編》凡例列「上海博物館藏戰國楚竹書(一)(二)」
- 「牌」「仰」——題記編號即墓號（「牌406.3」= 五里牌 406 號墓；「仰25.3」= 仰天湖 25 號墓）
- 「帛甲/乙/丙」——楚帛書依李零考釋分甲、乙、丙三篇
- 「天策」等六个——**归属**靠漢典跨欄實測（`src/probe_zdic_book_tabs.py`），
  **全称**靠小學堂出處表（`https://xiaoxue.iis.sinica.edu.tw/chuwenzi/Reference/Reference`，2026-10-31 取回）
- 「磚370」「秦1/13/99」「帛殘」——小學堂楚系庫出處表（2026-10-30 取回；56 條），
  全称与底本见 `books_xxt.csv`；**這幾條與漢典的「磚」「秦」不是同一件材料**

### `books_xxt.csv` 的列

| 列 | 含义 |
|----|------|
| `xxt_code` | 小學堂出處表的簡號（原文，如「天策」「雨21」「磚370」） |
| `corpus_full` | 文獻全稱（`出處表` 行照抄上游，不改一字；`派生` 行見 `note`） |
| `source_publication` | 摹本底本與版本 |
| `zdic_code` | 對應的漢典文獻代號；**對不上就留空**（留空不代表不收） |
| `row_kind` | `出處表` = 小學堂出處表原樣行；`派生` = 腳本按實測數據補的行 |
| `note` | 派生行寫明依據；**未核實的全稱保留〔待考〕標記** |
| `source_url` / `retrieved_at` | 出處表網址與取回時刻 |

由 `python src/build_books_xxt.py` 生成（可加 `--from-csv <出處表.csv>` 用新抓的表重算）。

## 出处链条

```
原簡帛（楚墓出土） → 考古整理本 → 《楚系簡帛文字編》（增訂本，湖北教育出版社，2008）摹本 → 漢典矢量化轉錄
```

每一层都如实标注：汉典的 CC0 放弃的是**汉典自己**的权利，不消灭摹本底本的著作权。
本仓库对字形及其底本**不主张任何权利**；权利人若有异议，按 `source_id` 整份移除。

`provenance/chu.jsonl` 里与底本有关的字段要分清两层：

| 字段 | 层级 | 内容 |
|------|------|------|
| `source_base_pages` | **字级** | 这个字在《楚系簡帛文字編》（增訂本）里的**页.行**，如「559.2」。同字有多个实例时含各实例的页。 |
| `source_references` | **字级** | 汉典字页底部「参考文献」栏的原文：这个字在汉典**各书体栏**下用到的全部底本（《楚系簡帛文字編》《睡虎地秦簡文字編》《秦簡牘文字編》《傳抄古文字編》《戰國文字編》等）。 |

两者都是**字级**而不是实例级：汉典的参考书目挂在「字页」上，不挂在单个实例上。
其余栏位（`source_book`、`book_part`、`source_number`、`source_id`）才是**实例级**的——
即「这个字形是哪个出土文献、哪篇、第几号」。

## 复跑

```bash
# 1) 字表：说文登记表 ∪ CJK 基本区
python src/build_char_table.py --out tmp/chars/basic.txt --blocks basic

# 2) 抓汉典楚系簡帛实例（每字 ≤5 条，每个出土文献 ≤1 条）
python src/fetch_zdic_glyphs.py --script chuwenzi --chars-file tmp/chars/basic.txt \
    --out tmp/zdic/chu-full --per-char 5 --max-per-book 1 --delay 0.25 --workers 4 \
    --source-dataset "汉典（zdic.net）楚系簡帛字形"

# 3) 补「摹本底本页.行」（离线推导，不联网；改了抽取逻辑时补跑）
python src/fetch_zdic_glyphs.py --script chuwenzi --out tmp/zdic/chu-full --backfill

# 4) 洗水印、剔位图
python src/clean_zdic_glyphs.py --manifest tmp/zdic/chu-full/manifest.json --out tmp/zdic/chu-clean

# 5) 合并（一字多形）+ 按文献代号筛选；不收的字形登记到 staged
#    --staged-csv-out 把登记表另存一份随层发布（字形本体不进层）
python src/merge_glyph_manifests.py --manifest tmp/zdic/chu-clean/manifest.json \
    --out tmp/zdic/chu-merged --keep-multi \
    --books-csv glyphs/chu/books.csv --staged-out tmp/zdic/chu-staged \
    --staged-csv-out glyphs/chu/staged.csv

# 6) 入库
python src/import_glyph_layer.py --manifest tmp/zdic/chu-merged/manifest.json --layer chu
```

### 增量重导：只改 `books.csv` 时不用重抓上游

改了 `books.csv` 的 `corpus_full` 或 `include`，**不必重抓十几万个上游 SVG**——
从已入库的层重建清单即可（条目号按整层内容重排，所以三步要连着跑）：

```bash
# 7) 从已入库的层重建清单
python src/rebuild_layer_manifest.py --layer chu --books glyphs/chu/books.csv \
    --out tmp/zdic/chu-rebuilt

# 8) 再合并一次（漢典矢量优先；--keep-multi 保住「一字多形」）
python src/merge_glyph_manifests.py --manifest tmp/zdic/chu-rebuilt/manifest.json \
    --keep-multi --out tmp/zdic/chu-merged --books-csv glyphs/chu/books.csv

# 9) 再入库一次
python src/import_glyph_layer.py --manifest tmp/zdic/chu-merged/manifest.json --layer chu
```

> **`source_book` 的取法有个坑**：`rebuild_layer_manifest.py` 要从题记原文（`variant`）
> 切出**含册次代号**的那一段（「上(1)」「上(2)」不能塌成「上」），
> 再用 `books.csv` 换全称——否则文献桶会从 26 掉到 25，`book_part` 也会整列丢失。
> 本轮 2026-10-31 重导就是先踩了这个坑再修好的；修好后差异只剩 `source_book` 465 条。

抓取脚本可断点续跑：清单里的 `visited` 记着查过哪些字，`selection_fingerprint`
钉住「选取逻辑」——改了脚本或改了参数，指纹对不上就当没有缓存、重新全抓。
