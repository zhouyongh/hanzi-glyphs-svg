# 古文字字形资源调研

> 目的：查清「甲骨 / 金文 / 小篆 / 隶书」的 SVG 字形**是否已有可下载的开源资源**，以及本仓库该怎么走。
> 时间：2026-10。**这是调研记录，不是出库清单**；入库前仍须按 `AGENTS.md` 逐条核实并写 provenance。

## 0. 核实口径（重要）

本文每条结论都标注来源强度，**不要把「二手」当「已核实」用**：

| 标记 | 含义 |
|------|------|
| **【一手·直连】** | 本项目在本机**直接打开原始页面 / API** 读到原文 |
| **【一手·代理】** | 本机直连不通，经第三方代理读到**原始 API 返回** |
| **【二手】** | 转引自他人 README、论文摘要或子任务报告，**未二次复核** |
| 【无法打开】 | 本机网络受限，**不代表资源不存在** |

**本机网络实测（2026-10）**：

- 直连可用：`github.com` / `raw.githubusercontent.com` / `api.github.com`、`zenodo.org`、`unicode.org`、`kanjivg.tagaini.net`、`dl.ndl.go.jp`（日本国立国会图书馆数字馆）
- **直连不通**：`*.wikimedia.org`（含 commons / upload / api.wikimedia）、`*.wikipedia.org`、`nature.com`（302 到 `idp.nature.com` 登录墙）、`huggingface.co`、`glyphwiki.org`(403)、`creazilla.com`(403)、`ndlsearch.ndl.go.jp`
  - Commons 内容可**经 `api.cors.lol` 代理**读取官方 API（见 §2）,但**下载文件本身仍需你自备代理**
- **地域封锁**：中研院 `xiaoxue.iis.sinica.edu.tw` 回「Access Restricted — 该国家或地区未开放」；`cdp.sinica.edu.tw` 下载区对非台湾 IP 回 401
- **明确禁止再利用**：早稻田大学古典籍总合数据库首页原文写明「未經本館許可，禁止用於電視放映、出版物、網頁等」→ **不可作底本** 【一手·直连】

**工具约束**：本会话 `pwsh` **完全不可用**（连 `echo hello` 都失败，退出码 `0xC0000142`），因此本轮无法下载、切字、校验 sha256，全部结论只来自 HTTP 读取。落库前需要先修这个。

## 1. 结论摘要

1. **甲骨文：有现成的、许可干净、自带出处的 SVG 数据集** —— Zenodo `10.5281/zenodo.22467946`，**1,203 个字形，CC BY 4.0**。这是本轮最重要的发现。
2. **小篆：出处骨架刚刚被 Unicode 补齐** —— Unicode 18.0（2026-09-02）编码 **Seal 区 `U+3D000..U+3FC3F`，11,328 码位**，`SealSources.txt` 为每个码位提供四个《说文》版本的序号 + 现代字 + 部首。现成 SVG 另有 Commons《说文》**540 部首全套**（CC BY-SA 3.0）与**单字 3,123 档**。
3. **金文 / 隶书：没有许可干净的现成矢量规模库**。隶书唯一成规模的来源是中研院小學堂「隸變」库（字形图片 CC0，但是**位图**，须自行描摹）。

## 5. 许可相容性 —— 发布策略必须先定

1. **CC0 是权利放弃声明，你只能放弃自己的权利，不能替上游放弃。** 对一批混入 CC BY-SA / OFL / 上游摹本的件统一声明 CC0 = **越权承诺**。
2. **ND / NC 一律禁入**（崇羲、白川、教育部、EVOBC…）。CC BY-SA 允许改作，**可以**入库但要署名 + 相同方式分享。
3. **现成来源的许可分布**：Commons = CC BY-SA 3.0（部分 PD）、CODH = CC BY-SA 4.0（部分 NC-SA）、CHISE IDS = GPL-2.0+。
   → **最兼容的做法：整体采用 CC BY-SA 4.0**；若坚持 CC0/MIT，就必须**分目录逐档标注许可**，并禁止 NC/ND/GPL 混入。
4. **字体导出 SVG 是灰色地带**【二手，条文来自 OFL 官方 FAQ】：
   - OFL FAQ 1.1 / 1.13 支持「用字体做出来的图形不继承 OFL」，§5 末句亦然；
   - 但 FAQ 1.25 对照：若产出物**仍是字体**则必须留 OFL；§1「individual components」射程未界定。
   - **保守做法：从 OFL 字体导出的 SVG 就用 OFL 发布**，文件内嵌 `<!-- Source: <font> <version> <URL>, OFL 1.1 -->`；**绝不用保留字名**做产品名。
5. **主路径应是「从公版底本描字」而不是「从现成字体导出」** —— 開元路线绕开了整个字体许可问题；字体导出只作校验/补充。
6. 建议在 `provenance.jsonl` 增加字段：`script`、`carrier`（刻本/拓片/摹本/字库）、`edition`、`page`/`frame`、`source_image_url`、`upstream_license_url`、`version`、`derived_from_sha256`、`review_status`。

## 6. 路线建议（按「能不能真正落地」排序）

**第 0 步 · 先改身份体系（不改就会一直返工）**
现规则 `glyphs/<书体>/<Unicode>.svg`（一个现代汉字一个文件）**在甲骨文上会直接崩掉**：

- 甲骨文**没有 Unicode 码位**（[SIL 现状页](https://writingsystems.info/scrlang/unicode/x-oracle-bone-unicode/)：*"The Oracle Bone script is not yet in Unicode… Blocks: None."*，2003 年提案至今未编码【一手·直连】）
- 一字多形是常态（Zenodo 数据集里 33 个现代字对应多条目）
- 存在未识字

→ 文件名改为**字形唯一标识**：`script` + 码位（小篆用篆书区块码位）/ 出处编号 + 异形序号。

**第 1 步 · 甲骨文（最快出成果，因为数据集现成）**
下载 Zenodo `v0.3`（CC BY 4.0）→ 逐字写 provenance（DOI + 文件名 + sha256 + `version`）→ **必须同时记录「源字库条目号」这一层转述出处** → 抽查 SVG 质量（注意作者自述的锐钩残环）。

**第 2 步 · 小篆（工作量最大但出处最硬）**
